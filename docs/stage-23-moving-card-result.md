## Метод

Карточка поворачивалась и меняла положение/масштаб, поэтому простой
горизонтальный сдвиг не подходит. Новый `road_motion_analysis_v01.py` оценивает
affine transform относительно первого кадра каждой серии: robust
forward-additive Lucas–Kanade, три масштаба, joint linear brightness scale/offset.
Последние нужны только для регистрации; исходные изображения и их профили
яркости не осветляются и не нормируются при выводе в общей grayscale шкале.
Использованы NumPy и стандартные библиотеки; пакеты не устанавливались.

Шаблон в crop: [355,45,555,210]. Предварительно принимается correlation≥0.75,
не менее 98% точек в кадре, determinant .65–1.4 и поворот менее 40°.
Проверена контактная таблица fitted polygons по всем фазам. Некорректные
fits, в том числе при выходе карточки из crop, отвергнуты.
Принято fits: 283/301, 226/293 и 254/294. Доли потерь различаются и могут
влиять на итоговую выборку; отвергнутые фрагменты не интерполируются.

Тонкая тёмная линия определяется по reference x=[392,438], y=[80,175].
Её наклон оценивается по строкам reference. Профиль усредняется по высоте
с поправкой на этот наклон; ни на каждом кадре, ни по результату резкости
линия заново не центрируется. Измеряется FWHM тёмной линии относительно
местного фона, горизонтальная ширина в reference pixels. Это apparent width,
включающая исходную толщину линии, оптику, ISP, интерполяцию и движение;
это НЕ отдельная длина PSF, sensor MTF или точность детекции.
Шаг профиля 0.25 пикселя — численный шаг, не заявленная точность измерения.

Скорость оценивается центральной разностью affine-положения точки около
линии: reference relative [-40,0]. Время — first-pixel exposure midpoint
SensorTimestamp − ExposureTime·500 нс. Для каждого соседнего интервала
проверяется 0<dt≤50 мс. На всех трёх кадрах требуется correlation≥0.85;
для центрального determinant .85–1.15, поворот менее 20°. Скорость приведена
к поперечному движению относительно reference-линии, согласованному с
горизонтальной шириной. Это пиксели/с, не км/ч.

Итоговых eligible кадров: 277 / 204 / 248. Пороговые значения, диапазон
скоростей и выбор линии уточнялись при исследовании данных: это
исследовательский анализ, не заранее зарегистрированное подтверждающее испытание.
Метод регистрации сам может зависеть от blur; независимый эталон движения
ещё нужен. Affine не компенсирует rolling shutter, перспективную деформацию
и все движения руки. Карточка не является моделью движения всей дорожной сцены.

## Результат при сопоставимой скорости

Медианы FWHM и квартильные интервалы — описательная статистика кадров.
Соседние кадры коррелированы; их число нельзя выдавать за независимые повторы.

| Режим | 0–20 пикс/с, медиана | 150–250 пикс/с, медиана | IQR на движении | Кадров в движении |
|---|---:|---:|---:|---:|
| Short | 2.75 | 5.50 | 5.00–6.00 | 117 |
| 4 мс + auto gain | 2.75 | 3.00 | 2.75–4.00 | 60 |
| Normal | 2.75 | 6.375 | 5.50–6.75 | 100 |

В данном проходе медианная apparent ширина на 4 мс меньше на 45.5% против
Short и на 52.9% против Normal. Это не «смаз уменьшился на столько-то»:
ширина включает базовую толщину линии и оптическое размытие. Медианный
относительный контраст на движении .453 против .229 / .182; разные уровни
яркости/шума не позволяют называть это универсальным выигрышем SNR.
В статичных/медленных кадрах apparent ширины почти одинаковы.

Для иллюстрации автоматически выбрана тройка по скорости и pose, без
использования linewidth/contrast: кандидаты 175–225 пикс/с, abs angle<10°,
determinant .9–1.1; между режимами speed spread≤12 пикс/с, angle spread≤4°,
determinant spread≤.08. Минимизировалось расстояние скоростей к 200 пикс/с
и расхождения pose. Выбраны Short frame 113 (198.56 пикс/с, width 5.75),
4 мс frame 98 (200.01, width 3.25), Normal frame 80 (199.26, width 6.25).
Геометрически выровненные crop и profiles показывают более узкую/глубокую
линию на 4 мс при меньшей общей яркости. Иллюстрация использует общий
диапазон grayscale 0–255; яркость исходных изображений не менялась.
Нормированный график профиля отдельно подписан как contrast/background.

## Что доказано и что дальше

В этой последовательной серии подтверждён полезный эффект компонента:
короткая выдержка с нативным gain лучше сохраняла тонкую линию при движении,
чем штатные Normal/Short, выбравшие 32.68 мс. Это поддерживает гипотезу
о пользе ограничения выдержки для движущейся камеры при достаточном свете.

Но испытывался фиксированный предел 4 мс, а не новая адаптивная политика.
Её глобальное превосходство, recall мусора, работа на дороге и пригодность
для всех условий не доказаны. До вывода об алгоритме нужны повторяемые
рандомизированные серии при разных скоростях/освещении, независимая проверка
скорости и сравнение с простым постоянным 4 мс как сильным baseline.
Следующая задача — выбирать предел по движению и расслаблять его на
статике, не теряя этот выигрыш и не портя шум/видимость при малом свете.

## Воспроизведение

Новый CLI `tools/analyze_motion_trial_v01.py` читает trial_* и сохраняет
fits, eligible CSV и report. Хеш источника affine fit записан в report.
Сначала fits рассчитаны непосредственно по всем кадрам (около 91 с на
Windows в этом запуске), затем использован cache тех же fits для расчёта
окончательной скорости/отбора. Cache проверяется по числу кадров, sensor
timestamps и экспозиции. Источник register_affine за это время не менялся.
Для независимого повторения omit --tracking-cache:

```powershell
python -B tools/analyze_motion_trial_v01.py runs/motion_20261026_001/motion_service_001 --output runs/motion_reanalysis_new --template-roi 355 45 555 210 --line-window 392 438 --line-y 80 175 --feature-relative -40 0
```

Четыре новых теста: known affine с поворотом/масштабом/brightness change,
рост ширины от известного box blur, отказ на плоской картинке/отсутствующей
линии, правильные timestamp velocities и исключение gap. Полный набор
реально выполнен: 110 тестов, 106 успешных, четыре ожидаемых падения старой
версии. Копия кода сделана до изменений. Аппаратный capture-код не менялся;
новые вычисления происходят только офлайн. Откат — прежние программы,
записи и предыдущие отчёты сохранены.
