# Запуск записи движения по кнопке

26 октября 2026. Пользователь подготовил отдельную полосатую карточку.
Свежий preview 5 с подтвердил, что она лежит рядом с основной мишенью.
Питание чистое, свободно около 2.21 ГБ, активных камерных процессов не было.
Новый AWB reference [1.8495323657989502, 2.0363900661468506] и LensPosition=0
зафиксированы для всех новых режимов. Они не переносятся задним числом
на предыдущий static опыт.

Новый `road_pi_motion_v01.py` добавляет bounded capture и временную локальную
страницу запуска. Сначала по кнопке прогревается камера и проверяются
readback/AE convergence, затем идёт отсчёт 5 с, после — 10 с записи.
Ожидание пользователя не занимает камеру и не пишет видео. Порядок первого
feasibility прохода: native Short, ручная выдержка 4 мс + auto gain,
native Normal. Один проход в фиксированном порядке не доказывает превосходство;
скорость и свет необходимо сопоставлять по фактическим данным, затем повторять.

Сохраняется кадр main Y без сжатия, crop [500,120,1080,440] в нативных
координатах 1920×1080. Размер 580×320, без изменения масштаба.
Это post-ISP Y, не sensor RAW. Для каждого файла сохранены metadata,
SensorTimestamp, actual controls и фактические промежутки между кадрами.
При медленной microSD пропуски не маскируются повторами. Данные записываются
после release request. Время наблюдения не подменяет время экспозиции.
Скорость мишени при захвате ещё не оценена; её предстоит измерить офлайн.

Три режима имеют одинаковые pipeline, crop, focus и фиксированный AWB.
Поддержка modes проверяется, частично отсутствующая mode metadata явно
помечается; косвенное подтверждение — активная AE и реальные controls.
Для ручных 4 мс допускается прежний предварительный readback envelope 42 мкс.
Плохое/неизвестное питание, stale/duplicate timestamp, неправильные controls,
ошибка массива/диска или deadline прекращают опыт с cleanup.

На серию: до 80 МБ, до 320 кадров и резерв microSD 1 ГБ. При текущем crop
300 массивов занимают около 56 МБ без metadata; реальные размеры измеряются.
Запрошена частота 30 fps, итоговый темп вычисляется по sensor timestamps.
Восемь HTTP обработчиков максимум, socket timeout 3 с, один camera worker,
повторные клики не ставят параллельный опыт в очередь. POST запуска требует
токен страницы. Сервис для доверенной LAN, не для доступа из интернета;
завершается примерно через 20 минут, активный короткий опыт имеет свой deadline.
Постоянного сервиса ОС и новых пакетов нет.

Страница по адресу Pi:8000 показывает референсный crop с поворотом 180°,
кнопку начала следующей серии, подготовку, отсчёт, запись и окончание.
Референс статичен, это не живая трансляция. Пользователь должен перемещать
карточку по полу в сторону свободного участка и обратно примерно на 10–15 см,
параллельно рулетке, сохраняя глубину и ориентацию; фактическая скорость
руками не задаётся точно и не может считаться одинаковой между сериями.
Мишень должна оставаться в показанной области, не закрываться рукой.

## Проверено

Четыре новых офлайн-теста проверили отсчёт до записи, связь файла с
SensorTimestamp, cleanup при stop/array failure, границы crop/duration,
атомарный отказ при 16 конкурентных повторных кликах.
Полный набор реально выполнен: 106 тестов, 102 успешных, четыре ожидаемых
падения старой версии. Перед изменениями сделана timestamped копия кода.

После тестов выполнен реальный неподвижный smoke: native Short, crop как выше,
1 с отсчёта и 2 с записи. Сохранён 61 кадр, максимальный sensor gap
33.324 мс, gaps >50 мс — ноль. Ошибок и cleanup failures нет; питание
throttled=0x0, 49.4°C, свободно 2199519232 байт после smoke.
Это проверка сохранения и каденса короткого фрагмента, не доказательство
производительности всего видеотракта или результатов на движении.

LAN страница реально вернула HTTP 200, status idle/completed=0/total=3.
На момент публикации этого отчёта пользовательские движущиеся серии
ещё не выполнены. Камера при ожидании закрыта. Следующий шаг — три
запуска по кнопке, затем анализ tracks/скоростей/смаза и поиск сопоставимых
по скорости кадров. Результаты без сопоставимых скоростей не дают победителя.

Данные smoke и будущих опытов остаются на Pi в новом каталоге
motion_service_001; локальные preview/reference и summary в игнорируемом
runs/motion_20261026_001. Домашние изображения не публикуются в GitHub.
На аппаратную часть добавлен только новый versioned Python-файл и служебная
картинка области записи; firmware/tuning/сетевые настройки не менялись.
Откат: остановить процесс motion-сервиса SIGTERM и использовать прежний live
адаптер. SIGTERM также прекращает активную серию с освобождением камеры.
