# Другая камера

[English](camera-adapters.md) · [Главная](../README.ru.md)

Готов только адаптер Picamera2 для IMX708. Замена `driver` не добавляет поддержку сенсора. Общий интерфейс — контракт разработки, а не загрузчик готовых драйверов.

См. [base.py](../src/road_camera_exposure/adapters/base.py) и [custom_camera.py](../examples/custom_camera.py). Реализуйте владение камерой, `capabilities()`, `read()`, `set_shutter()` и `close()` через SDK производителя. Шаблон специально выдаёт `NotImplementedError`.

1. Получайте видимую яркостную плоскость `uint8` без паддинга строки. Цветной поток сохраняйте отдельно.
2. Переводите выдержку в **микросекунды**, усиление — в документированные линейные коэффициенты. Для V4L2 `EXPOSURE_ABSOLUTE` по спецификации единица 100 мкс; проверьте реализацию и границы устройства. `exposure_to_device_units()` округляет вниз; фактическую настройку нужно прочитать обратно. Другие API могут использовать другие единицы.
3. Приведите реальное начало экспозиции к монотонным часам. `CapturedFrame.midpoint_ns` добавляет половину фактической выдержки. Время получения не равно времени экспозиции; не подставляйте выдуманные метаданные IP-камеры.
4. Проверьте совместимость ручной выдержки со штатным усилением. Иначе потребуется отдельная совместная политика усиления; универсальной замены здесь нет.
5. `set_shutter(None)` возвращает штатную выдержку. Команда может примениться через несколько кадров: используйте метаданные и `ControlGate`, а не только успешный возврат SDK.
6. Соедините `TargetTracker` и `ShutterPolicy` в цикле захвата. После проверки SDK добавьте backend в CLI/конфигурацию. Нужны реальные границы, освобождение камеры и лимиты журналов.

Другому CSI-сенсору нужны изменения режима, фокуса, метаданных и контролов. Программа проверяет IMX708 и выбирает определённый режим 1080p/2304×1296; снимать проверку без испытаний нельзя.

Для USB/UVC запросите контролы и взаимодействие авто/ручного режима. Для RTSP/IP одного декодированного кадра недостаточно: нужен документированный API производителя/ONVIF. Декодер добавляет нагрузку и задержку сверх опубликованного CPU-замера. Без управления и обратного чтения тот же замкнутый цикл не воспроизводится.

Проверки: единицы SDK → воспроизведение кадров → неподвижное применение команд → ограниченный опыт с движением → дорога. Вместе измеряйте задержку команд, пропуски, сигнал/шум, смаз, цвет, CPU и полную задержку. Другие камеры эти проверки здесь ещё не проходили.
