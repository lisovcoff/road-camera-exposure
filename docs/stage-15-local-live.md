# Локальная трансляция с регулированием экспозиции

26 октября 2026. Добавлены `road_pi_live_v01.py` и независимый от камеры
HTTP-модуль `road_live_http_v01.py`. Это демонстрационный сервис для доверенной
локальной сети без авторизации и TLS. Не предназначен для доступа из интернета.
Привязка к явно указанному частному IPv4, до трёх зрителей, до восьми HTTP
обработчиков; медленные соединения ограничены таймаутом. Очередь видео — один
последний JPEG до 3 МБ. Видео на диск не пишется. Телеметрия ограничена 80 МБ
и резервом 1 ГБ; запуск по умолчанию завершается через четыре часа.

Страница показывает видео, реальные ExposureTime, AnalogueGain, DigitalGain,
LensPosition, яркость и статусы ядра v02. Потеря соединения видна на странице.
Кнопка поворота влияет только на отображение, не на координаты анализа.
Замер — прежняя лабораторная центральная область, не дорожная калибровка.
Автомобильная скорость не подключена: профиль задаётся вручную, ядру передаётся
фиксированный синтетический вход 8 км/ч для сохранения режима DETECT.

`stationary` разрешает 100–32680 мкс, `road-lab` — 100–4000 мкс; усиление 2–16.
Приоритет короткой выдержки сохраняется, длинная используется при недостатке
экспозиции. Фокус 0.0 — кандидат прошлого опыта, не доказанный оптимум.
Калибровка readback прежняя, её измеренная область ограничена 12 мс;
расширение до 32.68 мс требует проверки на реальном изменении света.
Ошибка применения команд останавливает процесс, не скрывается переходом на AE.

## Запуск на Raspberry Pi

Из корня развёрнутого проекта; вместо IP и путей укажите свои значения:

```bash
python3 -B code/road_pi_live_v01.py --run-camera --bind 192.168.1.50 --profile stationary --duration 14400 --calibration /path/to/calibration.json --output /path/to/new-run
```

Нужны уже установленные Picamera2, NumPy и штатный кодировщик MJPEG. Новых
пакетов не устанавливалось. В браузере откройте `http://192.168.1.50:8000`.
Для остановки — Ctrl+C в терминале запуска или SIGTERM конкретному процессу.
Автозапуск при включении платы не установлен. Для проверки без камеры:

```powershell
python -B code/road_pi_live_v01.py
python -B -m unittest discover -s tests -p 'test_*.py'
python -B tools/probe_live_v01.py http://192.168.1.50:8000
```

Последняя команда использует Pillow на принимающем компьютере, декодирует
60 кадров без сохранения изображений. Это проверка приёма, не задержки
от физической сцены до экрана браузера.

## Фактически проверено

- 84 офлайн-теста: 80 успешных, четыре ожидаемых падения исторической v01.
- Сеть Wi-Fi уже настроена пользователем; подключение и SSH по её адресу
  проверены. Секреты не читались, настройки сети не менялись.
- Аппаратный запуск остановлен SIGTERM по просьбе пользователя через 106.9 с.
  3170 наблюдений, 49 команд и 49 подтверждений, ошибок и ошибок очистки нет.
- Кодировщик: 3225 JPEG, около 30.04 кадра/с за запуск.
- Приём по Wi-Fi-адресу из Windows: декодированы 60 кадров 1920×1080,
  3232276 байт за интервал прихода 1.931 с, около 30.55 кадра/с;
  наибольший промежуток между приходами 85.35 мс. Короткая выборка и
  буферизация не позволяют обещать стабильные 30 кадров/с в любой сети.
- Последний статус яркости Y≈92.7, выдержка 11410 мкс, gain 16;
  `NEAR_TARGET`, `UNCALIBRATED_ROI`. Питание throttled=0x0, после опыта 48.3°C.

Камера была направлена на потолок; проверка резкости предметов и перехода
свет→темнота→свет ещё НЕ проведена. Пользователь готовит сцену с отключением
питания. Сервис сейчас остановлен; длительный запуск ожидает готовности сцены.
Фото и журналы сохранены только в игнорируемом runs и каталоге опыта на Pi.

После проверки требуется направить камеру на контрастные предметы в 1–3 м,
проверить фокус и выполнить переключения света. В полной темноте детали
невосстановимы; длинная выдержка для неподвижной сцены не доказывает качество
изображения при движении машины. Ночное дорожное освещение предполагает фары.

Схема MJPEG сверена с [примером Raspberry Pi](https://github.com/raspberrypi/picamera2/blob/main/examples/mjpeg_server_2.py).
В Pi 5 фактический кодировщик программный; пример не является доказательством
аппаратного кодирования. Способ ввода Wi-Fi пароля через `nmcli --ask` описан
в [официальном руководстве](https://www.raspberrypi.com/documentation/computers/configuration.html).

Откат: остановить новый процесс и запускать прежние программы. Системные
настройки, прошивка, исходные эксперименты и программы не заменялись.
