# Как повторить аппаратные проверки и перейти к дороге

Текущий проверенный комплект — Raspberry Pi 5, IMX708 / Camera Module 3
Standard, Picamera2 0.3.37, libcamera 0.7.2, Python 3.13.5 и NumPy 2.2.4.
На другом комплекте сначала проверьте поддержку ручных контролов и API.
Скрипты ничего не устанавливают. Зависимости Pi должны уже присутствовать;
на Windows Picamera2 для dry-run и тестов не нужен.

## Лабораторная последовательность

Все команды ниже выполняются **на Raspberry Pi**, из корня копии репозитория.
Они запускают камеру только с `--run-camera`. Сначала — проверка без камеры:

```bash
python3 -B code/road_pi_observe_v01.py
python3 -B code/road_pi_controls_v02.py
python3 -B code/road_pi_loop_v02.py
python3 -B code/road_pi_encode_v01.py
df -h .
vcgencmd get_throttled
vcgencmd measure_temp
```

У dry-run ожидается `camera_started=false`. Для приведённых коротких опытов
потребуется менее 20 МБ на результаты и как минимум 1 ГБ свободного резерва;
при сомнительном питании или перегреве сначала устраните причину.
Убедитесь, что камеру не занимает другое приложение.

Создайте родительский каталог результатов; существующие данные не удаляются:

```bash
mkdir -p runs
```

Запускайте следующие команды по одной. Ожидаемый код успеха — 0; при ошибке
изучите новый `summary.json` и не переходите к следующему аппаратному этапу.
Для повтора выбирайте новые имена каталогов, например суффикс `_002`.

```bash
timeout --signal=INT --kill-after=5s 45s python3 -B code/road_pi_observe_v01.py --run-camera --allow-uncalibrated-lab --output runs/observe_001
timeout --signal=INT --kill-after=5s 50s python3 -B code/road_pi_controls_v02.py --run-camera --output runs/controls_001
timeout --signal=INT --kill-after=5s 45s python3 -B code/road_pi_loop_v02.py --run-camera --calibration runs/controls_001/calibration.json --output runs/loop_001
timeout --signal=INT --kill-after=5s 40s python3 -B code/road_pi_encode_v01.py --run-camera --codec h264 --output runs/h264_001
timeout --signal=INT --kill-after=5s 40s python3 -B code/road_pi_encode_v01.py --run-camera --codec mjpeg --output runs/mjpeg_001
timeout --signal=INT --kill-after=5s 50s python3 -B code/road_pi_encode_v01.py --run-camera --codec h264 --calibration runs/controls_001/calibration.json --output runs/h264_loop_001
```

Повторите последнюю команду с `--codec mjpeg` и новым output для второго
кодека. Не используйте результаты калибровки от другого режима/ПО/камеры.
Совпадение строкового Model не идентифицирует физический серийный экземпляр;
после замены камеры или изменения условий повторите измерения.

Первый опыт даёт setup, JSONL, до трёх JPEG и summary. Калибровка должна дать
`accepted=true`. Замкнутые опыты — `error=null`, пустые cleanup errors,
число подтверждённых команд равно числу отправленных, pending пуст.
У кодирования дополнительно проверяются packet error, PTS, успешное
декодирование первых пакетов и размер кадра. См. фактические результаты
[регулятора](stage-10-closed-loop.md) и [совместного опыта](stage-12-encoded-loop.md).

Настройки 4000/8000 мкс, gain 2…16, speed SIMULATED и лабораторный прямоугольник
служат проверке программы. Это не дорожный профиль. LensPosition=1,0 не
подтверждает фокус на нужном расстоянии. HDR здесь не переключается и
независимо не подтверждён. Версии v01 сохранены для истории; первый loop v01
на реальном оборудовании не прошёл, для текущей последовательности нужен v02.

## Что необходимо подготовить физически

Для следующего опыта нужна достаточно освещённая сцена с различимыми
деталями и масштабом: контрастные кромки, линейка и предметы 1, 2, 3 см на
нескольких измеренных расстояниях. Текущая тёмная комнатная сцена не позволяет
оценивать фокус и сохранность мелких деталей. Для выбора дорожного ROI нужны
собственные кадры Module 3 из реального места установки.

Запишите размеры установки, сохранив точку отсчёта:

| Величина | Что измерить |
|---|---|
| Высота | Оптический центр камеры над асфальтом, ориентир 1,5 м |
| Смещение от передней части | Насколько камера позади передней части машины |
| Ближняя граница | Минимальное расстояние нужной зоны от передней части |
| Дальняя граница | Ориентир 4,5 м от передней части, не от объектива |
| Ширина | Общая ширина требуемых двух полос в метрах |
| Установка | Наклон/поворот, ориентация изображения, наличие стекла и отражений |

Отметьте границы зоны на земле и положите масштабные метки у её углов и
в центре. Проверьте, что все требуемые границы видны одновременно. Если
оптика не охватывает их, это нужно зафиксировать как ограничение конструкции,
а не скрывать сужением зоны или обрезкой изображения. Маски старого
регистратора здесь не используются.

## Приёмочные проверки качества

Проводите сравнения на одних и тех же мишенях, расстояниях и освещении.
Сначала неподвижная установка: подбор фокуса по ближней/дальней/боковым
мишеням, затем сравнение автоэкспозиции и ручных ограничений 2/4/8 мс.
Сохраняйте фактические exposure/gain/digital gain, режим, focus, crop и время.
Не считайте рост резкости от шума реальным улучшением деталей.

Далее — повторяемое движение и световые переходы, включая фары и мокрый
асфальт. Измеряйте ширину смазанной кромки в пикселях относительно неподвижного
кадра, различимость объектов 1–3 см, временной шум на ровном участке,
пересветы по зонам, время восстановления и стабильность управления.
Одна целевая яркость не является критерием качества.

На одинаковом материале сравните H.264/MJPEG по сохранности объектов,
нагрузке, задержке и потоку данных. После выбора режима потребуется
длительный прогон с контролем питания, температуры, памяти и потерь.
Короткие лабораторные результаты не заменяют эту проверку.

Сетевой этап начнётся после выбора устройства-приёмника и Ethernet/Wi-Fi.
Тогда можно измерить задержку до потребителя, поведение при обрыве и
переполнении очередей. Сейчас видеосервис в сеть не открыт.
