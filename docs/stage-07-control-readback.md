# Этап 7: выдержка, усиление и задержка применения

22 октября 2026 года. Выполнена ограниченная серия ручного управления IMX708:
12 ступеней по 18 наблюдений плюс 6 стартовых кадров. Новая программа
`code/road_pi_controls_v01.py` по умолчанию печатает dry-run без камеры.
Штатные tuning и HDR не менялись; AE явно выключена, AF — manual, положение
линзы 1,0 является только лабораторной фиксацией. Сетевых сервисов нет.

## Метод и результат

После каждого запроса журнал содержит время начала/возврата `set_controls`,
параметры запроса, фактические метаданные того же request и статистику Y.
Стабильность проверяется по последним шести наблюдениям ступени. Совпадение
учитывается только для кадров, экспозиция которых началась после отправки.
Первая ступень повторяет стартовую настройку и не считается измерением задержки.

| Запрошенная выдержка, мкс | Фактическая, мкс | Ошибка, мкс |
|---|---|---|
| 2000 | 1977 | 23 |
| 4000 | 3981 | 19 |
| 8000 | 7989 | 11 |
| 12000 | 11997 | 3 |

На проверенных ступенях gain 2, 4, 8 и 16 в устойчивой части совпал с запросом.
Серия принята: 216 записанных наблюдений, все 12 устойчивых ступеней,
без ошибок захвата и cleanup. На 11 переходах первое совпадение появилось
в наблюдении с индексом 10 (индекс начинается с нуля):

- отправка → начало экспозиции первого совпавшего кадра: 328,47…336,61 мс;
- отправка → наблюдение его метаданных: 363,51…367,19 мс.

Это задержка данного программного пути и настройки буферов, а не чистая
электрическая задержка сенсора. Между всеми записанными SensorTimestamp
нет повторов; максимальный промежуток 233,253 мс показывает, что выборка
не доказывает непрерывный учёт каждого кадра. Кодировщик здесь не работал.

Для следующего лабораторного опыта получены допуски 25 мкс и 0,01 gain:
максимальная наблюдённая ошибка плюс небольшой запас. Они относятся к
проверенным точкам и режиму; непрерывный диапазон gain не откалиброван.
При несовпадении регулятор должен остановить отправку по тайм-ауту, а не
расширять допуски автоматически. Результат `calibration.json` содержит
режим, версии и модель для проверки совместимости следующего опыта.

## Ресурсы и проверки

Перед запуском: 2 241 925 120 байт свободно, throttled=0x0, 48,8 °C.
Выходные данные — 207 341 байт, без JPEG и видео. После: 2 241 630 208 байт,
throttled=0x0, 47,7 °C; CPU-время процесса 0,758 с. Предел цикла — 20 с,
внешний watchdog — 40 с с INT и дополнительными 5 с до KILL.

Команда **на Raspberry Pi**, из нового каталога с зависимостями:

```bash
timeout --signal=INT --kill-after=5s 40s python3 -B code/road_pi_controls_v01.py --run-camera --output run_001
```

Получен код 0. Новый исходник проверен SHA-256 перед выполнением.
Результаты локально: `runs/pi_controls_20261022_01/run_001/`, не публикуются.

Команды **в Windows PowerShell**:

```powershell
python -B code/road_pi_controls_v01.py
python -B -m unittest discover -s tests -p 'test_controls_v01.py' -v
```

Dry-run не запускает камеру. Три новых теста прошли: задержанное применение
на имитаторе, отказ при нестабильных/неполных/несовпавших данных и освобождение
request/камеры при ошибке. Они не заменяют описанный аппаратный запуск.
Полный набор перед коммитом: 65 тестов, 61 успешный и 4 ожидаемых падения v0.1.

## Изменения и следующий этап

Добавлены новая версия программы, её тесты, этот отчёт; обновлена ссылка README.
Старые исходники сохранены, до изменений сделана резервная копия. На Pi
создан новый каталог, пакеты и системная конфигурация не менялись. Откат:
использовать прежние программы; процесс опыта уже закрыт, удаления не нужны.

Следующий этап — один замкнутый лабораторный цикл с одним запросом в полёте,
тайм-аутом и проверкой фактического readback. Зоны, яркость, скорость и фокус
остаются лабораторными; дорожное качество этим не подтверждено.

Семантика AE и ручных параметров проверена по
[документации libcamera](https://docs.libcamera.org/master/internal-api/namespacelibcamera_1_1controls.html)
и [руководству Picamera2](https://datasheets.raspberrypi.com/camera/picamera2-manual.pdf).
