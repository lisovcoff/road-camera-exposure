# Этап 11: H.264 и MJPEG без сетевой передачи

22 октября 2026 года. `road_pi_encode_v01.py` проверяет основной поток
1920×1080 YUV420 и одновременно анализирует lores. Два отдельных прогона
по 8 с выполнены при ручных 4000 мкс / gain 16; AE выключена, фокус manual
1,0. Команды регулятора на этом этапе не отправлялись.

Выход кодировщика принимается объектом Picamera2 Output, считающим размеры,
PTS и время прибытия пакетов. Видео на диск не записывается. В RAM остаются
до шести пакетов, суммарно не более 3 МБ, для декодирования после измерения.
Ограничения: 600 пакетов, 100 МБ обработанных байт, 5 МБ выходных журналов,
резерв microSD 1 ГБ, watchdog 40 с. Переполнение фиксируется в потоке
кодировщика и прекращает опыт через основной поток.

## Измерения

| Метрика | H.264 | MJPEG |
|---|---|---|
| Настройка | 8 Мбит/с, 2 потока, GOP 30 | QP 5, потоки библиотеки |
| Реальный класс | LibavH264Encoder | LibavMjpegEncoder |
| Выходные видеопакеты | 241 | 241 |
| Частота по PTS, пакетов/с | 30,0104 | 30,0104 |
| Максимальный промежуток PTS | 33,334 мс | 33,323 мс |
| Медиана readout → sink | 62,79 мс | 58,95 мс |
| Максимум readout → sink | 120,71 мс | 59,72 мс |
| Средний поток по PTS | 8,157 Мбит/с | 6,060 Мбит/с |
| Обработано кодированных данных | 8 154 236 байт | 6 058 253 байт |
| CPU-время до проверки декодером | 6,833 с | 5,075 с |
| Wall-время с подготовкой/прогревом/drain | 12,157 с | 9,558 с |
| Файлы на карте | 207 994 байт | 211 569 байт |
| Выбранные наблюдения lores | 224 | 229 |
| Проверка первых 6 пакетов | 6 кадров 1920×1080 | 6 кадров 1920×1080 |

Разница между числом lores-наблюдений и пакетов важна: это разные измерения.
Наблюдатель не учитывает каждый промежуточный кадр кодировщика. В данной
реализации libav выходной видеопакет соответствует кодированному изображению;
декодированием проверены только первые шесть, а не весь поток.

Readout → sink вычислен из SensorTimestamp через `encoder.firsttimestamp`
и относительный PTS в микросекундах. Соответствующий метод установленного
Picamera2 0.3.37 прочитан перед опытом. Это **не** задержка от начала экспозиции
до экрана или нейросети: отсутствуют сеть, буферы приёмника и его обработка.
CPU-время включает подготовку, прогрев и завершение, исключает последующее
декодирование; это не устойчивый процент общей загрузки платы.

Оба запуска завершились с кодом 0, без ошибок capture/encoder/decode/cleanup.
После H.264 throttled=0x0, 50,5 °C; после MJPEG throttled=0x0, 47,2 °C.
После двух опытов свободно 2 239 422 464 байт. Новых пакетов ПО нет.

## Ограничения сравнения

Сцена тёмная и неподвижная, мелкие детали различимы плохо. Низкая сложность
изображения не представляет дорогу с движущейся текстурой. Настройки качества
двух кодеков не эквивалентны; меньший поток MJPEG здесь не делает его
универсально лучшим. Нельзя выбрать кодек для окурков по этой таблице.
Нужны сравнения сохранности объектов на одинаковых исходных дорожных кадрах
и проверка приёмника. Длительный нагрев и надёжность также не проверены.

## Воспроизведение и изменения

**На Raspberry Pi**, из каталога с зависимостями, каждый output новый:

```bash
timeout --signal=INT --kill-after=5s 40s python3 -B code/road_pi_encode_v01.py --run-camera --codec h264 --output h264_001
timeout --signal=INT --kill-after=5s 40s python3 -B code/road_pi_encode_v01.py --run-camera --codec mjpeg --output mjpeg_001
```

**В Windows PowerShell**:

```powershell
python -B code/road_pi_encode_v01.py
python -B -m unittest discover -s tests -p 'test_encode_v01.py' -v
```

Четыре новых теста прошли: ограничения пакетов/времени/памяти, lifecycle
имитатора и отказ при неуспешном декодировании. Полный набор — 77 проверок,
73 успешных и 4 ожидаемых падения v0.1. Проверки имитатора не измеряют кодеки.

Добавлены новая программа, тесты, отчёт и ссылка README. Предварительно
создана резервная копия. Старые файлы и опыты не заменялись, постоянных
изменений системы нет. Локальные результаты:
`runs/pi_encode_20261022_01/{h264_001,mjpeg_001}/`, не входят в Git.
Откат — использовать прежние версии, процессы завершены.

Следующий этап — совместный опыт регулятора и кодировщика. Подключение сети
остаётся открытым до выбора приёмника и Ethernet/Wi-Fi.

API и программные кодировщики Pi 5 описаны в
[руководстве Picamera2](https://datasheets.raspberrypi.com/camera/picamera2-manual.pdf).
