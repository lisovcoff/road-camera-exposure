# Этап 4: кандидаты масок и проверка наложений

21 октября 2026 года. Подготовлены три варианта зон измерения экспозиции и
инструмент локального просмотра. Это **предварительные маски для анализа**,
не калиброванная область до 4,5 м и не подтверждение охвата двух полос.
Полное выходное изображение не обрезается. На Pi ничего не запускалось.

## Созданные файлы

- `code/road_masks_v01.py`: выпуклые нормированные полигоны, исключения,
  разбиение по строкам на зоны left/center/right. NumPy, без Pillow/камеры.
- `configs/road_roi_candidate_v01.json`: три явных варианта, равные веса
  зон как исходный вариант сравнения, признак `calibrated=false`.
- `tools/preview_road_roi_v01.py`: чтение JPEG внутри ZIP, наложения и отчёт;
  дополнительных файлов в архиве не меняет и полную распаковку не выполняет.
- `requirements-preview.txt`: отдельная необязательная зависимость Pillow
  для просмотра. Пакеты на этом этапе не устанавливались.
- `tests/test_road_masks_v01.py`: 10 проверок координат, исключений и условий
  переноса. README обновлён; ядро v0.2 и прежние исходники не изменены.

## Что именно проверено

Дневной набор прочитан с двумя вариантами, ночной — с третьим: всего 300
расчётов по 200 уникальным JPEG. На каждый вариант сохранены 12 наложений
и контактный лист 3×4. Визуально просмотрены все три листа, то есть 36
миниатюр. Это не просмотр каждого из 200 JPEG в полном разрешении.

| Вариант | Пикселей left / center / right при 320×240 | Медианы зон по 100 кадрам |
|---|---|---|
| left_road_reference, день | 7225 / 7219 / 7225 | 128 / 148 / 107,5 |
| forward_road_reference, день | 6966 / 6989 / 6966 | 148,5 / 109 / 96,5 |
| night_road_reference, ночь | 8337 / 8339 / 8337 | 43 / 45 / 41 |

Яркость здесь — Pillow RGB→L после уменьшения JPEG до 320×240. Это не sensor Y,
измерение шума, SNR или целевые значения для регулятора. Отличия от предыдущей
статистики закономерны: изменились выбранные области и способ уменьшения.

Цвета: голубой — слева, зелёный — центр, оранжевый — справа. Красные контуры
обозначают исключённые верхнюю и нижнюю полосы изображения. Жёлтый прямоугольник
показывает предполагаемую статическую помеху для проверки: он **не исключён**
из статистики. Неизвестное отражение не должно незаметно удалить участок дороги.

## Результат визуальной проверки

**left_road_reference отклонён как постоянная маска для всего дневного набора.**
Он подходит по направлению некоторым сценам с дорогой слева, но на других
захватывает газон разделительной полосы, встречное направление и отражения
в нижней левой части. Вариант оставлен для воспроизводимого сравнения, а не
для автоматического применения.

**forward_road_reference остаётся кандидатом, не готовым рабочим профилем.**
На ряде прямых участков лучше совпадает с дорожным полотном. Однако в других
кадрах включает часть обочины/газона или движущиеся автомобили. Фиксированные
полигоны не являются сегментатором дороги, а маленькие изображения недостаточны
для окончательной проверки границ. Дорожные тени при этом остаются внутри зон.

**night_road_reference на просмотренных примерах преимущественно захватывает
ближний асфальт**, одновременно освещённые и тёмные части. Возможны включения
обочины/ограждения и автомобилей; ночная темнота затрудняет проверку края.
Нельзя сделать вывод, что это ровно область до 4,5 м или шириной две полосы.
Имя отражает исходный пример, а не разрешение выбирать эту геометрию
автоматически при наступлении ночи.

Отражения кабины местами накладываются прямо на асфальт выше нижней исключённой
полосы. Их полное вырезание отнимет полезную рабочую область. Нужно проверить
прилегание матовой бленды к стеклу, положение камеры и чистоту стекла, а затем
повторить оценку. Экспозиция не восстанавливает детали, потерянные из-за
оптического наложения или недостаточного разрешения.

## Координаты и условия использования

Координаты — доли ширины/высоты по границам изображения [0,1]. Маска выбирает
центры пикселей. Разрешены только выпуклые непересекающиеся по обходу полигоны;
проверяются форма, конечность координат, диапазон и ненулевая площадь.

Полигон дороги делится на три части по его горизонтальному сечению в каждой
строке. Затем применяются исключения. Исключённая помеха не сдвигает границы
всех оставшихся зон. Равные веса пока не откалиброваны по качеству дороги.

Проверяется соответствие transform и соотношения сторон. Текущие маски
нарисованы для исходного 4:3. Попытка перенести их на 320×180 или повернуть
изображение без новой разметки завершается ошибкой. Сами по себе совпадающее
соотношение сторон и transform не доказывают совпадение оптики/позы; настройки
на другой камере всё равно требуют нового обзора. Максимальная сторона
маски ограничена 4096 пикселями для ограничения выделения памяти.

## Команды и полученные результаты

В Windows PowerShell из корня проекта:

```powershell
python -B -m unittest discover -s tests -p 'test_road_masks_v01.py' -v
python -B -m unittest discover -s tests -p 'test_*.py' -v
```

Получено 10/10 новых тестов и 48 проверок всего: 44 успешных, 4 ожидаемых
падения исторической v0.1. Проверены обход полигона в обе стороны, граница
по центрам пикселей, недопустимые полигоны, непересечение/полнота зон,
неизменность границ при исключении, сохранение тёмной дороги, отклонение
неверного crop/transform и запрет выдавать кандидаты за калиброванную маску.

Для своих локальных данных укажите существующий путь к ZIP:

```powershell
$datasetZip = Read-Host 'Полный путь к ZIP'
python -B tools/preview_road_roi_v01.py --archive $datasetZip --profile forward_road_reference
```

Ожидается `Read 100 images; saved 12 previews and contact_sheet.png` и путь
к новому каталогу внутри `runs/`. Требуется уже доступный Pillow; проверена
установленная версия 12.2.0. В текущем
инструменте проверка ограничена исходными JPEG 2592×1944; неподходящие размеры
не преобразуются молча. Допустимы до 300 JPEG по 5 МБ, до 1000 ZIP-записей и
до 1 ГБ заявленного распакованного объёма. Файл с более широкими bounds не
принимается даже при небольшом сжатом размере.

Сохраняются до 12 PNG 640×480, контактный лист 1920×1920, JSON со статистикой
всех кадров, SHA-256 ZIP/конфига и копия конфигурации. `--output` допускает
только новый каталог внутри игнорируемого `runs/`; повторное использование
каталога отклоняется. Источник не распаковывается по путям из архива.
Порядок превью — сортировка имён JPEG, не порядок XML и не проверенное время.

Три выполненных просмотра находятся локально в:

- `runs/roi_review_004_day_left_001/`;
- `runs/roi_review_004_day_forward_001/`;
- `runs/roi_review_004_night_001/`.

39 PNG и отчёты занимают около 31 МБ. Исходные архивы не менялись;
ни изображения, ни локальные отчёты не включены в Git. Для первых трёх
просмотров SHA конфигурации записан в отчёте и совпадает с опубликованным
конфигом; автоматическое сохранение копии конфига добавлено после их создания.
На отдельном синтетическом JPEG дополнительно проверены создание наложения,
копирование конфига, отказ повторно использовать каталог и отказ писать
результат за пределами `runs/`. Это программная проверка вывода, не дорожный
опыт; её два PNG хранятся в отдельном локальном smoke-каталоге.

## Следующий шаг

До управления камерой нужно связать область измерения с реальной геометрией
установки и подтвердить допустимость помех. Для следующего программного шага
можно подготовить наблюдающий адаптер с явно предварительной маской и
покадровым журналом. Он должен только рассчитывать рекомендации, без
притворного подтверждения неотправленных команд и без попытки навязать
параметры домашней сцены дороге.

Запуск съёмки, запись на Pi и подача команд требуют отдельно согласованного
ограниченного опыта. Даже удачная маска на старом JPEG не подтверждает
пригодность объектива Pi для требуемых ширины и расстояний.
