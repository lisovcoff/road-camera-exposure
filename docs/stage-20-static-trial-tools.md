# Подготовка первого измерительного опыта

26 октября 2026. Этот этап полностью офлайн: SSH, камера и новые сетевые
сервисы не использовались. Подготовлены bounded adapter, анализатор и план.
Новый расчёт движения из этапа 19 пока не отправляет controls на оборудование.
Сначала нужны реальные характеристики шума, response и вариантов штатной AGC.

## Программа опыта

`code/road_pi_trial_v01.py` поддерживает три режима:

| Режим | Выдержка | Усиление |
|---|---|---|
| native-normal | штатная AE Normal | штатная AGC |
| native-short | штатная AE Short | штатная AGC |
| shutter-auto-gain | заданная вручную | штатная AGC |

Фокус фиксирован явным LensPosition. AWB выключена, ColourGains одинаковые
для сравниваемых серий и предварительно измерены по опорному освещению.
Это изоляция AE; при смене спектра света цвет может выглядеть иначе.
Нужна отдельная серия с обычной AWB после основного измерения.
Внутренний ISP и tuning не заменяются, HDR не переключается.

Перед измерением ожидаются три свежих совпадающих readback и минимум 2 с
прогрева, AeState=Converged; общий предел ожидания — 5 с. Подтверждаются
экспозиция для ручного режима, фокус и ColourGains. Modes проверяются, если
они пришли в metadata. Отсутствие поля отмечается как косвенное подтверждение
через активную AE, а не скрывается. Дрейф controls прекращает опыт.
Штатная AE может считать себя converged и при нехватке света; это не успех
по качеству изображения. Контроль цифрового усиления — наблюдение, не обещание 1×.

Выдержка ручной серии ограничена 100–12000 мкс: запас readback 42 мкс
взят из прежней ограниченной калибровки и остаётся предварительным для
новой комбинации manual shutter/auto gain. Отклонение больше допуска
останавливает опыт; новый допуск не расширяется автоматически.

Sensor/main/lores как в прежних опытах: 2304×1296 10 bit, main 1920×1080
YUV420, lores 320×180, transform identity, 30 fps запрошены.
Видеокодирование отсутствует. Частота наблюдений около 10 Гц (зависит от
кадров и обработки); это не измерение скорости видеопередачи.

## Данные и границы интерпретации

Две явные непересекающиеся области target/background размером 8–64 пикселя
на сторону задаются по свежему main-кадру. Это плоские однородные участки
мишени и соседнего фона, не метки дорожной геометрии и не ROI нейросети.
Раз в секунду из одного request сохраняются два небольших uint8 Y массива
без JPEG-сжатия. Это результат ISP, не сенсорный RAW. До трёх JPEG сцены
и полные metadata сохраняются из тех же запросов для визуальной проверки.

`tools/analyze_static_trial_v01.py` выдаёт распределения actual exposure/gain/
digital gain/frame duration, контраст target-background и временную вариацию
пар участков. Используются неперекрывающиеся пары кадров:
sqrt(mean(var(Y2-Y1))/2). Текстура неподвижной сцены вычитается, но движение,
мерцание, обработка ISP и корреляции temporal denoise мешают оценке шума.
Это post-ISP proxy; он не является EMVA1288 SNR, noise electrons или детекцией.

При дрейфе средней яркости >2 Y, диапазоне экспозиции >42 мкс или gain >0.05
статистическая стационарность помечается нарушенной, contrast/variation proxy
не выдаётся. Пороговые значения — диагностические, не калибровка камеры.
Нулевая вариация не превращается в бесконечный CNR: результат None с причиной.
Недостаточно кадров также запрещает proxy. Даже прошедшие проверки не
доказывают одинаковый свет и неподвижность; JPEG/мишень проверяются отдельно.
Автоматического выбора победителя нет.

Проверяется совместимость actual camera configuration, software versions,
областей, фокуса и ColourGains между сериями. Идентичный signature не доказывает
одинаковый свет. Повреждённые/незавершённые опыты отвергаются. NumPy pickle
не используется; путь patch не может выходить из каталога опыта.

## Бюджет и порядок запуска

На серию: 5–30 с измерений плюс до 5 с прогрева, общий deadline duration+7 с,
20 МБ выходных данных, до 3 JPEG по 3 МБ, резерв microSD не менее 1 ГБ.
Проверяется питание каждые две секунды, неизвестный или плохой статус
прекращает опыт. Requests освобождаются в finally, camera stop/close также
вызываются при ошибке. Новый output создаётся эксклюзивно, прежние не заменяются.

План `configs/static_trial_plan_v01.json` включает Normal, Short и выдержки
1/2/4/8 мс со штатным gain. По 10 с, шесть серий — до 120 МБ по предельному
бюджету; это ещё не замер реального размера. Порядок рандомизируется при
сохранении освещения. Сначала один уровень света; следующий после проверки
качества сохранения. К motion-тесту переходят после действительного readback
и выбора подходящих рабочих диапазонов.

Без камеры, Windows PowerShell:

```powershell
python -B code/road_pi_trial_v01.py --mode native-short
python -B -m unittest discover -s tests -p 'test_*.py'
```

Ожидается camera_started=false и 102 теста: 98 успешных, четыре ожидаемых
падения старой версии. Dry-run не импортирует Picamera2 и не создаёт опыт.

Пример на Raspberry Pi, только после подстановки измеренных координат,
фокуса и ColourGains; ниже значения условные, НЕ готовые для текущей сцены:

```bash
python3 -B code/road_pi_trial_v01.py --run-camera --allow-uncalibrated-lab --mode shutter-auto-gain --exposure-us 4000 --lens 0.35 --colour-gains 2.0 1.8 --target-roi 100 100 116 116 --background-roi 130 100 146 116 --duration 10 --output new_trial_001
```

Анализ на Windows после копирования новых каталогов:

```powershell
python -B tools/analyze_static_trial_v01.py runs/trial_normal runs/trial_short runs/trial_hybrid --output runs/new_static_analysis.json
```

Успешный CLI сообщает число серий, compatible_configuration, winner=null.
Выход создаётся новым файлом, выводы не перезаписываются.

## Реально выполненная проверка

Восемь новых тестов охватывают три режима acquisition, задержанное применение,
отказ по неверным modes/AWB/неизвестной AE, release/stop/close при сбое,
недоступные controls и плохое питание, безопасные пути, оценку вариации на
известном синтетическом шуме и запрет proxy при дрейфе. Все прошли.
Полный набор: 102 теста, 98 успешных, четыре ожидаемых падения.
Дополнительно три полностью синтетические серии сохранены в
runs/static_trial_offline_20261026_001 с маркировкой FAKE_CAMERA_ONLY.
CLI анализатора реально прочитал их; аппаратных данных в них нет.

## Что потребуется от пользователя

Теперь камера нужна для первой калибровочной серии. Достаточно подключить Pi
к питанию и прежней Wi-Fi сети, закрепить камеру, оставить комнатный свет
постоянным и положить на пол контрастную плоскую мишень с линейкой. По свежему
предпросмотру выберем два участка, фокус и общий AWB reference. Мишень пока
не двигать. Бумажки полезны для расположения; фактические размеры и диапазон
различимости надо измерить. Повторяемое движение понадобится следующим этапом.

Перед правками сделана резервная копия. Добавлены только новые версии файлов,
план и документация, README обновлён. На Pi ничего не развёрнуто. Откат —
использовать прежние программы; тестовые данные находятся в игнорируемом runs.
